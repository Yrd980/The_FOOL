# V0.2 Architecture Restructure — Design Spec

## 1. Context

AI Pixel War 是一个多 AI 角色像素画布对抗与叙事模拟系统。V0.1 MVP 已完成引擎、Viewer、profiles 和 replay 管道。V0.2 的首要任务是解决架构债务，为后续功能迭代建立可维护的基础。

### 代码现状

| 模块 | 文件 | 行数 | 核心问题 |
|------|------|------|----------|
| Viewer 前端 | `viewer/src/App.tsx` | ~1140 | 所有 UI、状态、渲染逻辑耦合在单文件 |
| 主引擎 | `src/engine.ts` + `src/engine/*.ts` | ~560 (engine.ts) | `mythColorForPoint` 在 engine.ts 出现 11 次；同类回调模式遍布 canvasRuntime、decisionService、strategyService、twinFactory |
| LLM 客户端 | `src/deepseekClient.ts` | ~180 | 硬绑定 DeepSeek，无提供者抽象 |
| Replay 格式 | `src/types.ts` | — | 无版本号，schema 变更破坏旧回放 |
| 项目基建 | — | — | 无 CLAUDE.md、无测试、无 docs 目录 |

## 2. Goals

1. 将 App.tsx 从 1140 行拆分到 <500 行主文件 + 独立组件/hooks
2. 消除 engine.ts 中的重复回调传递
3. 建立 LLM 提供者抽象层
4. 为 replay 格式添加版本控制
5. 建立项目级 CLAUDE.md 和文档结构

## 3. Non-Goals

- 不改变 replay 数据内容或新增字段（仅加版本号）
- 不新增 Viewer 功能（纯重构）
- 不替换 DeepSeek 为其他提供者（仅建立抽象）

## 4. Design

### 4.1 Viewer 组件化拆分

```
viewer/src/
  App.tsx                     # 顶层布局 + 状态协调（<500行）
  hooks/
    useReplayData.ts          # replay 加载、轮询、列表管理
    usePlaybackControl.ts     # 回合/步骤播放状态机
    useCanvasRenderer.ts      # canvas 绘制逻辑（从 useEffect 提取）
  components/
    BattleCanvas.tsx           # canvas 元素 + 播放控制条 + 进度条
    ReplaySelector.tsx         # replay 列表选择 + 刷新
    RoundPulse.tsx             # 回合指标 + 排名列表
    SocialHeat.tsx             # 社交指标面板（alliances, rivalries, tension）
    PublicVoice.tsx            # 公开发言列表
    PrivateWire.tsx            # 私聊列表
    PersonaNotes.tsx           # 人格注释列表
    TwinLens.tsx               # 角色详情 + 情绪 + 关系卡片
    ArtMission.tsx             # AI Mission：主题、mood words、palette、motifs
    MetricCard.tsx             # 指标小卡片（已有，需独立提取）
    RelationCard.tsx           # 关系卡片（已有，需独立提取）
```

**拆分原则：**
- 每个组件接收 props，不直接管理全局状态
- 复杂状态逻辑提取到 hooks
- App.tsx 负责 hooks 调用和 props 分发
- 组件间通过 App.tsx 中的状态协调，不引入状态管理库

### 4.2 EngineContext 简化回调

问题范围：`mythColorForPoint` 在 `engine.ts` 中出现 11 次（包含 lambda 构造和函数调用），同类参数传递模式还在 `canvasRuntime.ts`、`decisionService.ts`、`strategyService.ts`、`twinFactory.ts` 中重复。引入统一上下文对象：

```ts
// src/engine/engineContext.ts
import type { CanvasCell } from "./canvasRuntime";  // CanvasCell 定义在 canvasRuntime.ts line 5
import type { AgentState, ArtDirection, ArtZone } from "../types";

export interface EngineContext {
  board: CanvasCell[][];
  width: number;
  height: number;
  artDirection: ArtDirection;
  artTargetColors: string[][];
  renderPalette: string[];
  mythColorForPoint(agent: AgentState, x: number, y: number, color: string, round: number): string;
  zoneWeight(zone: ArtZone, x: number, y: number): number;
}
```

**循环导入处理：** `CanvasCell` 当前定义在 `canvasRuntime.ts`。`engineContext.ts` 从 `canvasRuntime.ts` 导入 `CanvasCell`，而 `canvasRuntime.ts` 的函数将接收 `EngineContext`。这不会形成循环，因为 `engineContext.ts` 只导入类型（type-only import），TypeScript 编译器会消除运行时依赖。使用 `import type` 确保安全。如果后续出现问题，备选方案是将 `CanvasCell` 移至 `types.ts`。

- `PixelWarEngine` 构造函数中创建一个 `EngineContext` 实例
- `engine.ts` 和所有 `engine/*.ts` 子模块中需要这些参数的函数改为接收 `ctx: EngineContext`
- 消除 `engine.ts` 中约 100 行的重复 lambda 构造代码，同时简化子模块的函数签名

### 4.3 LLM 提供者抽象

```ts
// src/llm/types.ts
export interface LLMProvider {
  readonly modelName: string;
  generateDecision(params: {
    systemPrompt: string;
    userPrompt: string;
    temperature?: number;
  }): Promise<unknown>;
}

// src/llm/deepseekProvider.ts
export class DeepSeekProvider implements LLMProvider { ... }

// 将来: src/llm/openaiProvider.ts, src/llm/claudeProvider.ts
```

- `PixelWarEngine` 构造函数接收 `LLMProvider` 而非 `DeepSeekClient`
- `buildAgentSystemPrompt` 和 `buildAgentUserPrompt` 移至 `src/llm/prompts.ts`
- `extractJsonObject` 移至 `src/llm/jsonExtractor.ts`

### 4.4 Replay 版本化

**引擎端：** 在 `SimulationResult` 中添加：

```ts
export interface SimulationResult {
  schema_version: string;  // 运行时值，如 "1.0"
  // ... 其余字段不变
}
```

`engine.ts` 的 `run()` 方法在构造返回对象时写入 `schema_version: "1.0"`。版本字符串定义为常量放在 `constants.ts` 中。

**Viewer 端：** `useReplayData.ts`（新建的 hook）在解析 replay JSON 后检查 `schema_version`：
- 无版本字段 → 视为 `"0.9"`（兼容旧文件），正常加载
- 版本 major 不匹配 → 在 UI 顶部显示黄色提示条，告知用户可能存在不兼容，但仍尝试加载
- 不使用字面量类型（`"1.0"` 作为类型），因为需要在运行时比较版本字符串

### 4.5 项目 CLAUDE.md

```markdown
# AI Pixel War

## Tech Stack
- Runtime: Bun
- Language: TypeScript (strict)
- Frontend: React 18 + Tailwind CSS 4 + Vite
- LLM: DeepSeek API (default), abstracted via LLMProvider
- Validation: AJV 2020

## Commands
- `bun run typecheck` — 类型检查
- `bun run check` — lint
- `bun run viewer:build` — 构建 Viewer
- `bun audit` — 安全审计

## Conventions
- Replay schema 变更必须同步更新 PRD.md 和 schema_version
- 组件文件 <300 行，超出需拆分
- 提交前必须通过 typecheck
```

删除以下 Codex 格式文件：

PRD.md 保留，更新以下内容：

## 5. Implementation Order

1. 建立 `docs/` 目录和 CLAUDE.md
2. 废弃旧文档文件
3. Viewer 组件化拆分（最大工作量）
4. EngineContext 引入
5. LLM 提供者抽象
6. Replay 版本化
7. 更新 PRD.md

## 6. Risks

- Viewer 拆分可能引入渲染 bug → 需要在每一步验证画布和播放功能
- EngineContext 修改面广 → 需要确保所有 engine/ 子模块的调用签名同步更新
- 旧 replay 文件兼容 → 版本检查逻辑需要处理 `undefined` 版本字段

## 7. Success Criteria

- [ ] App.tsx 主文件 <500 行
- [ ] `mythColorForPoint` lambda 构造在整个 `src/` 中只出现 1 次（在 `EngineContext` 创建处）
- [ ] `bun run typecheck` 通过
- [ ] `bun run viewer:build` 成功
- [ ] 旧 replay 文件仍可在 Viewer 中加载
- [ ] CLAUDE.md 存在且内容准确
