# V0.2 Feature Backlog — Design Spec

## 1. Context

架构重构完成后，以下功能缺口需要补齐。这些需求均来自代码分析而非臆想——每一项都对应代码中已定义但未完整实现的能力，或 Viewer 中已有数据但未展示的信息。

## 2. Features

### 2.1 Viewer 错误面板

**现状：** replay 每回合的 `errors` 数组包含 `schema_validation`、`schema_repaired`、`decision_generation` 三类错误，但 Viewer 没有展示。

**设计：**
- 新增 `ErrorPanel.tsx` 组件
- 在 Round Pulse 下方显示当前回合的错误列表
- 按错误类型着色：validation=红、repaired=黄、generation=橙
- 显示 agent_id、错误详情
- 无错误时不显示面板

### 2.2 Treaty 系统完善（joint_attack）

**现状：** `TreatyProposal` 类型定义了 `"joint_attack"` 类型和 `target_enemy_id` 字段，但 `socialState.ts` 中的 `updateTreaties` 只处理 `"no_attack"`。

**设计：**

类型变更：
- `Treaty` 接口（`types.ts` line 81）：`type` 从 `"no_attack"` 改为 `"no_attack" | "joint_attack"`，新增 `target_enemy_id?: string`（joint_attack 时必填）
- `MemoryEventType` 联合类型（`types.ts` line 36）：新增 `"joint_attack_signed"` 和 `"joint_attack_broken"`

逻辑变更：
- `socialState.ts` `updateTreaties`（line 291）：新增 `joint_attack` 签署分支，参考 `hasNoAttackTreaty` 模式新建 `hasJointAttackTreaty` 函数
- `socialState.ts` `describeSharedEvent` 和 `buildLastRoundSummary`：新增对 `joint_attack_signed` / `joint_attack_broken` 的 switch 分支
- `canvasRuntime.ts` invade 判定逻辑（line 409 附近的 attackPower 计算）：当攻击方与某 agent 有 joint_attack 条约且目标为条约中的 `target_enemy_id` 时，attackPower +15%
- 联合攻击方之间的 invade 自动失败（互不侵犯副作用）

- 过期和毁约逻辑与 no_attack 一致

### 2.3 Replay 筛选

**现状：** Viewer 的 replay 选择器只显示文件列表，无筛选能力。

**设计：**

API 改动（`viewerServer.ts`）：
- 当前 `replayList()` 只读 `fs.statSync` 元数据（name, mtime, bytes），不解析 JSON 内容
- 扩展 `replayList()` 为每个 replay 文件额外读取前 512 字节，提取 `config.dry_run` 和 `config.agent_count`（这两个字段在 JSON 的头部）
- 返回形状扩展为 `{ name, mtime, bytes, mode: "dry-run" | "live", agent_count: number }`
- 支持 query 参数：`?mode=dry-run|live&agents_min=N&agents_max=N`，在服务端过滤

Viewer 端（`ReplaySelector.tsx`，架构重构后新组件）：
- 加筛选 UI：模式切换、agent 数量范围
- 列表按时间倒序，显示 agent count 和 mode 标签

### 2.4 排名面板显示名字

**现状：** 排名列表显示 `agent_id`（UUID 截断），不直观。

**设计：**
- 在 `RoundPulse.tsx`（架构重构后新建的组件，从 App.tsx 提取）中排名项从 `item.id` 改为 `item.name`（通过 `agentDirectory` 查找）
- 保留 ID 作为 tooltip 或小字标注
- 注：依赖 Viewer 组件化完成后才能实施

### 2.5 CLI 改进

**现状：** 手写 parser，无 help，未知参数静默忽略。

**设计：**
- 加 `--help` 或 `-h` 输出参数说明
- 未知参数 → 输出 warning 到 stderr
- 参数越界时的错误消息补充实际值（当前已包含范围如 `"width must be 8-256"`，需追加 `, got 1024`）
- 不引入 CLI 框架，保持手写实现

### 2.6 Mock Agent 消息个性化

**现状：** `mockAgent.ts` 中 `buildPublicMessage` 和 `buildPrivateMessage` 使用少量硬编码英文模板，只根据 speech_style 大类分支。这两个函数本身是确定性的（不使用 `Math.random`），但模板池太小，缺乏角色个性。另外，`pickIntent`（line 109, 113）中使用了 `Math.random()` 做决策，导致 dry-run 模式非确定性。

**设计：**
- 扩展消息模板池，每个 intent × speech_style 组合至少 3 条候选
- 消息中穿插 agent 的 core_values 关键词和 archetype 标签
- 私聊消息引用 `recent_shared_events` 中的具体事件
- 使用 `stablePairBias` 选择模板索引（函数已存在于 mockAgent.ts line 33）
- 修复 `pickIntent` 中两处 `Math.random()` 调用（line 109, 113），改用 `stablePairBias` 使 dry-run 确定性

### 2.7 单元测试

**现状：** 项目零测试文件。

**设计：**
- 测试框架：Bun 内置 test runner（`bun test`）
- 优先覆盖纯函数模块：
  1. `scoreboard.ts` — 评分计算
  2. `socialState.ts` — 关系更新、条约处理
  3. `canvasRuntime.ts` — 画布操作判定
  4. `decisionNormalizer.ts` — schema 修复逻辑
- 测试文件放在 `src/__tests__/` 目录
- 每个模块至少覆盖正常路径 + 边界条件

## 3. Priority Order

| 优先级 | 功能 | 依赖 |
|--------|------|------|
| P0 | 单元测试 | 无（可与架构重构并行） |
| P0 | 排名显示名字 | Viewer 组件化完成后 |
| P1 | 错误面板 | Viewer 组件化完成后 |
| P1 | CLI 改进 | 无 |
| P2 | Mock Agent 个性化 | 无 |
| P2 | Replay 筛选 | Viewer 组件化 + API 改动 |
| P3 | Treaty joint_attack | engine 重构完成后 |

## 4. Success Criteria

- [ ] Viewer 错误面板在有 errors 的回合正确显示
- [ ] joint_attack 条约可在 dry-run 中触发并在 replay 中体现
- [ ] Replay 筛选可按 mode 过滤
- [ ] 排名面板显示角色名而非 ID
- [ ] `--help` 输出完整参数说明
- [ ] Mock 消息包含角色个性关键词
- [ ] `bun test` 通过且覆盖 `scoreboard.ts`、`socialState.ts`、`canvasRuntime.ts`、`decisionNormalizer.ts`
- 注：`socialState.ts` 测试应设计为易于扩展，以便 P3 treaty 工作完成后追加 joint_attack 相关用例
